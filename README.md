## :fire:ゲーム内容
　このゲームはダダサバイバーのような2D見下ろし型アクションゲームです。ゲームでよくある「やられちゃった」の常識を覆すゲーム性を組み込みたいとチームで考え、敵から魂をかき集め、体力を回復したり、特殊なお墓を出現させて敵を倒したり、無敵になって脱出する能力を駆使してたくさんの敵を倒すゲームを作っています。まだ製作途中です。
  
## :wrench:プロジェクト概要
- **製作期間**: 2025年10月14日 ~ 現在制作中
- **目標**: UnityRoomにアップする
- **開発体制**: ５人（基本プログラマー、素材探し、絵描きなどできるものから）
- **AI制約**: 開発方針や設計など、画像素材の作成
- **自分のロール**：プロジェクト管理、メインプログラム、ドット絵制作
## :hammer:開発環境
- **Engine**: ```Unity 6000.2.6f2```
- **Platform**: WebGL
- **Version管理**: Git / Github Desktop
- **タスク管理**: Github issues, Github project
## :art:制作方法
　MTGを定期的に開いて、新しいアイデアを出したり、アイデアに対する解像度を上げるようにしています。実際の開発では可能な開発方針を決めてGithubのissuesにタスクをまとめてメンバーに振り分けることで制作を進めていっています。  
 
　自分の役割はメインプログラムで、このゲームのシステムの根幹やメンバーが見てわかるような開発テンプレートの制作に力を入れています。たまにドット絵で武器やアイテムなどを書いたりしています。タスク作成や役割分担も行っています。
## :rocket:工夫点
- プログラミングが苦手なメンバーでも参加できるようにできました。開発テンプレートや拡張性の高いシステムを構築することで、AIを用いてもプロジェクト全体を崩さないように開発ができます。

- 拡張性の高いシステムを構築できたこと。StatusVectorSystemというアクションゲームにおけるステータス管理を簡単にするシステムを構築しました。MonoBehaviourクラスを継承したクラスは一つしか使っていないので、Unity以外の環境でも汎用的に使うことができます。「*Assets\Common\SVSystem*」このフォルダーにシステム全体が入っています。※オブジェクト指向の言語だけかもしれません。

- CanvaやGoogleスプレッドシートなどを用いて視覚的に開発状況を把握できるにしたこと。

- UnityのEditor機能を活用することでゲーム制作に必要なUI操作を独自に追加することができた。

## :adhesive_bandage:反省点
- プログラミングをうまく教えれなかったこと。できればみんなにプログラミングが書けるようになってもらって、自在に構築することができるようにしたかったのですがまだまだでした。

- プログラミング以外の技術が足らないこと。プログラミングだけではいいゲームにならないことに気が付き、公開されているアセットを利用したり、描ける部分は自分で描くことで補おうと思います。

- MTG時間の少なさ。MTGを定期的に開かないとなかなかモチベーションが保てないことに気が付き、定期的に開けるように頑張っています。
